# Launcher 1.6.9 hotfix design

## Goal

Publish a safe `1.6.9` launcher update that replaces the unusable `1.6.8`
update artifact, restores updater error-modal behavior, removes the bypass
button, and restores proportional window resizing from the Electron version.

The existing `v1.6.8` tag and GitHub Release remain immutable. The backend
updater manifest is switched to `1.6.9` only after all local and CI gates pass.

## Root causes

### Incompatible launcher-update signature

The local release used minisign 0.12 and generated the stream-verifiable `ED`
format. GitHub Actions installed an unpinned minisign package and published a
legacy `Ed` signature. The available public workflow metadata does not expose
the installed tool version, but the decoded published signature proves that
the CI signing behavior differed from the pinned local tool. The Rust
`minisign-verify` `StreamVerifier`
intentionally rejects legacy signatures because it can verify only the
prehashed streaming format.

The runtime verifier is correct and remains strict. The release pipeline must
produce and verify `ED` signatures before any upload or backend publication.

### Updater error modal

`renderer_launcher_update.js` displays errors through `showErrorModal`, but the
updater page never calls `setupErrorModal`. Therefore the `#error-modal-ok`
button has no click handler.

The updater error path also creates `#continue-without-update` dynamically.
That bypass is no longer desired and will be removed.

### Fixed-size Tauri window

The Electron windows were resizable and constrained with `setAspectRatio`.
The Tauri configuration explicitly sets `resizable: false`, and Tauri has no
public equivalent of Electron's aspect-ratio setter on Windows.

## Design

### Signed release pipeline

- GitHub Actions installs an explicitly pinned minisign 0.12 binary and prints
  its version before invoking the release script.
- The release script rejects any unsupported minisign version before building.
- After signing, the script verifies with minisign's prehash-required mode and
  validates that the decoded signature algorithm marker is exactly `ED`.
- The same validation is applied when reusing an existing GitHub Release.
- Signature validation occurs before uploading artifacts and before the admin
  API activates a manifest.
- The Rust launcher continues using `StreamVerifier`; legacy `Ed` signatures
  are not accepted and the artifact is never loaded wholly into memory.

This makes a repeat of `1.6.8` fail closed inside CI instead of publishing an
artifact that launchers cannot apply.

### Updater error UI

- The updater renderer calls `setupErrorModal()` during module initialization,
  matching the install and main pages.
- Clicking `#error-modal-ok` hides the modal.
- Clicking the modal backdrop continues to hide it.
- `ensureContinueButton` and all creation/navigation logic for
  `#continue-without-update` are removed.
- On update failure the user may acknowledge the error and close the launcher;
  the launcher does not silently bypass an update that it already classified
  as available.

### Proportional Windows resizing

- The Tauri window becomes resizable.
- Initial logical sizes remain unchanged and become the new minimum sizes:
  - main/intro/install: `892 x 496`;
  - launcher updater: `788 x 272`.
- The corresponding aspect ratios are `892:496` and `788:272`.
- A Windows-only native window subclass handles `WM_SIZING` and adjusts the
  proposed outer rectangle before Windows paints it. The dragged edge or corner
  remains anchored, so resizing is smooth and does not visibly snap afterward.
- `set_window_layout` updates the active ratio and minimum size when navigation
  changes between updater and normal pages, then applies the page's default
  size and centers the window as it does today.
- Native state is owned for the lifetime of the window and released on
  `WM_NCDESTROY`. Reapplying a layout updates existing state rather than
  installing duplicate subclasses.
- Non-Windows builds keep the normal Tauri resizable/minimum-size behavior and
  do not compile the Windows hook. Production remains Windows-only.

## Error handling and safety

- Failure to install or update the Windows aspect-ratio hook is returned as a
  structured Tauri command error; navigation still proceeds because the
  frontend navigation contract already tolerates layout errors.
- Rectangle arithmetic uses checked/saturating conversion and enforces positive
  dimensions and configured minimums.
- The release pipeline never overwrites `v1.6.8` and never uses force-push.
- `1.6.9` becomes active only after the signed GitHub Release exists and its
  manifest identity has been verified.

## Tests

Tests are added before production changes and observed failing for the intended
reason.

- PowerShell release test: accepts an `ED` fixture and rejects an `Ed` fixture.
- Browser updater test: an update error appears, clicking “Понял” hides it, and
  `#continue-without-update` is absent.
- Rust unit tests: edge/corner rectangle calculations preserve the active ratio,
  respect minimum dimensions, and leave the anchored sides stable.
- Configuration/release test: the production Tauri window is resizable.
- Focused JS, PowerShell, Rust formatting and relevant Rust tests run after the
  complete hotfix batch.
- A single full `scripts/release.ps1 -Version 1.6.9` gate runs before publishing.
- After CI publication, the public manifest, portable EXE size/SHA-256/minisign,
  site download redirect, and update discovery from `1.6.7` and `1.6.8` are
  verified independently.

## Rollout

1. Commit the tested hotfix and version bump as `1.6.9`.
2. Build and sign locally through the sole release entrypoint.
3. Push `tauri-rework` normally and create the immutable `v1.6.9` tag.
4. Let GitHub Actions run the same release script with `-Publish`.
5. Verify the published signature marker is `ED` before considering the update
   usable.
6. Confirm the backend and public website download endpoint point to `1.6.9`.

## Non-goals

- Supporting legacy minisign signatures in the launcher.
- Replacing the current CMD update helper in this hotfix.
- Redesigning HTML/CSS or adding arbitrary free-form window resizing.
- Modifying or deleting the existing `v1.6.8` release.
